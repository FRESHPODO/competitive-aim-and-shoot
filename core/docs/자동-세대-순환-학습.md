# 단일 PPO · 자동 세대 순환 학습

작성일: 2026-11-04. 구현: `unity_bridge/train_generational.py`, 실행 화면: `unity_bridge/generation_trainer.py`.

## 목적과 학습 대상

서로 다른 조준 노이즈·원본 조준 보상 조건·자신의 PPO 보상 비율 α·공통 게임 조건에서 사용할 격발 결정 PPO **하나**를 학습한다. A의 PPO만 갱신한다. 원본 SAC 조준 모델과 B의 격발 정책은 갱신하지 않는다. 경쟁은 경기 안에 남고, 상대의 학습 과정과 학습자 갱신을 분리한다.

이 구조는 여러 전문 모델을 학습한 뒤 합치는 증류가 아니다. 처음부터 조건을 입력받는 단일 정책을 여러 조건의 경기 경험으로 갱신한다. 구현은 CPU 병렬 경기 + 단일 CPU PPO 갱신이다.

## 실행과 설정

상위 폴더의 **Start-Generational-Trainer.cmd**를 실행한다. 기존 학습기·수동 상대 순환 학습기와 별도 프로그램이다.

화면 순서는 `학습자 A 조준 조건 / A PPO 보상 / 공통 게임 조건 / B PPO 보상 / B 조준 조건`이다.

| 설정 | 의미 | 기본값 |
|---|---|---|
| 총 학습 경기 수 | A와 B가 함께 치르는 누적 경기 수. 결정 횟수가 아님 | 150,000 |
| 경기 제한 | 한 경기의 실제 시뮬레이션 시간 상한. PPO 입력에는 없음 | 12초 |
| 세대 교체 주기 | 이 경기 수의 배수에서 학습자 복사본을 상대 목록에 등록 | 10,000경기 |
| 최근 상대 세대 수 | 동등한 확률로 선택할 최근 복사본 개수 | 3, 선택 가능 2 또는 3 |
| 갱신당 경기 수 | 같은 학습자 정책 버전으로 모으는 경기 묶음의 최대 크기 | 16 |
| 병렬 경기 수 | 별도 CPU 시뮬레이션 프로세스 수 | 0: 자원 기준 최대 4 자동 선택 |
| 복구 저장 간격 | 최근 모델·옵티마이저·난수 상태·상대 목록의 복구 저장 간격 | 60초 |
| Seed | 조건 추출과 경기 난수의 기준. 빈칸이면 실행 시 무작위 지정 | 빈칸 |

고정값 또는 범위의 최소·최대·추출 단위를 설정한다. 범위 추출은 `최소 + k × 단위 <= 최대`인 값들에 대해 균등하다. α도 같은 규칙을 쓰며, 화면에 실제 성공 보상 `+2α`, 실패 비용 `−2(1−α)`를 함께 표시한다. 무승부 보상은 0이다. 이는 성공 확률을 설정하는 기능이 아니다.

조준 프리셋은 A와 B 각각 여러 개 선택한다. 매 경기 각자의 목록에서 하나를 균등·독립 추출한다. 프로/아마추어 평균뿐 아니라 플레이어별 원 추정값 프리셋도 선택할 수 있다. `프로 원값 전체`, `아마추어 원값 전체`는 화면에 표시하는 플레이어별 흰색·익숙한 감도 조건을 선택한다.

프리셋은 운동·위치·속도·시계 노이즈와 원본 조준의 성공 보상·실패 비용·두 감쇠 값, 총 8개를 그대로 적용한다. 수치 표의 커스텀 조건을 사용하려면 `커스텀 범위도 추출 후보에 포함`을 선택한다. 프리셋과 커스텀을 함께 선택하면 커스텀도 하나의 후보로 동일 확률을 가진다. 프리셋을 뽑은 경기에서는 해당 8개 값에 커스텀 범위를 추가로 섞지 않는다.

상대 모델 세대 선택과 상대 조준 프리셋 선택은 별개다. 예를 들어 같은 3세대 격발 모델을 프로 원값과 아마추어 원값 조건에서 각각 사용할 수 있다. B의 α도 지정 범위에서 경기마다 추출하며, 고정된 B 정책이 자신의 α를 입력받아 판단한다.

공통 게임 조건은 표적 체력·치명타 반지름 비율·표적 반지름·속도·외곽 피해·중앙 피해·발사 쿨다운·중앙 치명타 즉사 여부다. 양쪽에 같은 공격 조건을 적용한다. 이 학습기는 총기 종류나 탄 퍼짐 옵션을 제공하지 않으며 탄 퍼짐은 비활성화한다.

## 경기 수에 따른 세대 교체

1. 새 학습은 무작위 초기화한 A의 PPO로 시작한다. 처음에는 B의 상대 목록에 **무보류 상대 하나만** 있다.
2. 무보류 상대는 원본 조준 모델이 유효한 발사 요청을 냈을 때 모두 승인한다. 원본 발사 요청이 없는 상태에서 발사를 만들거나 쿨다운을 무시하지 않는다.
3. A는 선택된 여러 조준 조건과 α에서 경기하고, A의 요청 시점 경험만 학습에 사용한다. B의 경험은 PPO 갱신에 넣지 않는다.
4. 지정 경기 수에 도달한 묶음의 PPO 갱신을 끝낸 뒤 A의 가중치를 복사한다. 이 복사본이 첫 상대 세대다. **등록 직후부터 무보류 상대를 목록에서 제거**한다.
5. 이후에는 최근 2~3세대 중 하나를 매 경기 균등 선택한다. 새 세대가 들어오면 초과한 오래된 세대를 상대 목록과 디스크에서 제거한다. 영구 세대 기록에는 번호·등록 경기 수·해시 등 작은 메타데이터만 남긴다.
6. 생성된 상대는 이후 추가 학습하지 않는다. 계속 갱신하는 것은 A의 모델 하나다.

예: 교체 주기 10,000경기, 유지 3세대.

| 경기를 시작할 때의 누적 완료 수 | 사용 가능한 상대 |
|---|---|
| 0~9,999 | 무보류 |
| 10,000~19,999 | 1세대 |
| 20,000~29,999 | 1·2세대 |
| 30,000~39,999 | 1·2·3세대 |
| 40,000~49,999 | 2·3·4세대 |

갱신당 경기 수가 교체 주기와 나누어떨어지지 않아도 경계 직전 묶음을 줄인다. 10,000번째 경기를 넘어 이전 상대 목록으로 미리 수집하지 않는다. 병렬 경기 완료 순서와 무관하게 경기 번호 순서로 경험을 모은다.

유효한 PPO 갱신을 한 번도 할 수 없었다면 무작위 모델을 ‘학습된 첫 상대’로 등록하지 않는다. 이때는 무보류 상대가 유지된다. 세대 등록은 승률 평가를 통과했다는 의미가 아니라, 정해진 경기 수 시점의 학습자 복사본이라는 의미다.

## 관측과 행동 제한

기존 관측 v7의 22항목과 발사 계획 규칙을 그대로 사용한다. 상대 모델 번호·상대 노이즈·상대 α는 정책 입력에 넣지 않는다. 경기 로그에 기록하는 상대 세대나 프리셋은 검증용 정보이며 PPO 입력과 별개다.

자신의 노이즈 4개, 자신의 α, 공통 게임 조건, 현재 표적 체력과 자신/상대의 남은 쿨다운, 원본 조준 모델의 믿음에서 계산한 후보 피해·오차·발사 계획을 사용한다. 완벽한 실제 피해나 미래 노이즈 결과를 입력하지 않는다. [전체 입력 명세](PPO-관측-v7.md).

원본 조준이 발사를 요청하지 않으면 PPO는 실행하지 않는다. 실제 제안 발사 시각이 쿨다운보다 이르면 추적 후 다음 BUMP에서 재판단한다. 승인한 계획은 실제 발사까지 취소하지 않는다. 남은 경기 시간·경과 시간·상태 갱신 후 경과 시간은 추가하지 않는다.

조건부 정책의 개념은 `πθ(승인/보류 | 관측, 자신의 조건, 자신의 α)`다. 상대 내부 조건이 숨겨져 있으므로 상대별 완벽한 대응을 보장하는 모델이 아니다. 관측으로 구분할 수 없는 상대들에 대해서는 학습 중 상대 혼합분포에 대한 판단을 학습한다. 현재 입력은 원본 조준의 8개 파라미터 전체를 직접 제공하지 않으므로, 새로운 조준 모델의 차이가 현재 후보 추정치와 자신의 노이즈에 드러나지 않으면 조건 구분에 한계가 있다.

## 연구 근거와 이번 구현의 구분

| 구성 | 확인한 연구 근거 | 이번 구현의 범위 |
|---|---|---|
| 정책으로 경험을 수집한 뒤 묶음 단위 갱신 | Schulman 외, PPO, 2017 | 같은 학습자 버전의 A 경험을 수집하고 PPO로 갱신. 과거 상대의 경험을 학습자 경험처럼 재사용하지 않음 |
| 여러 과거 정책을 섞은 상대에 대응 | Lanctot 외, PSRO, NeurIPS 2017 | 여러 고정 정책을 상대로 학습하는 발상에 근거. 메타게임 보수 행렬이나 균형 혼합비 계산은 구현하지 않음 |
| 서로 다른 조건을 하나의 함수에 제공 | Schaul 외, UVFA, ICML 2015 | 목표 조건부 가치 함수의 개념과 관련. 이 프로젝트의 α 조건부 정책 자체가 해당 논문에서 검증된 것은 아님 |
| 경기마다 조건 다양화 | Tobin 외, domain randomization, IROS 2017 | 시뮬레이터 조건을 다양화한다는 발상에 근거. 해당 논문은 시각 인식의 현실 전이를 다루며, 본 게임의 성능 향상을 입증하지 않음 |

**최근 2~3세대만 보관하는 것, 균등한 상대 선택, 고정 경기 수 교체, 첫 세대 이후 무보류 상대 제거는 사용자 요구에 따른 실험 설계다.** 위 논문들로 이 조합의 최적성·수렴·성능 개선을 주장할 수 없다. 이 구현은 완전한 PSRO나 Nash 균형 계산기가 아니다. 서로 다른 α를 가진 경쟁은 일반적으로 영합 보상으로 고정되지 않으므로 영합 게임의 보장도 그대로 적용할 수 없다.

최근 세대만 남기는 것은 오래된 상대가 계속 잔존하는 문제와 저장 용량을 줄이지만, 오래된 전략에 대한 망각이나 전략 순환의 위험을 높일 수 있다. 무보류 상대 제거 후 그 상대에 대한 성능이 유지되는지도 별도로 평가해야 한다. 학습 화면의 승률은 상대 혼합과 조건이 계속 변하는 중의 값이므로 세대 간 실력 향상의 직접 지표가 아니다.

권장 검증은 학습과 분리된 고정 평가 목록에서 실시한다. 무보류 상대, 과거의 대표 세대, 학습에 쓰지 않은 조준 프리셋·시드를 평가에만 사용하고, 동일한 상대·조건·α별 승/패/무·보류 비율·발사 수를 비교한다. 과거 상대는 학습 목록에 재투입하지 않더라도 외부 평가용으로 별도 보관할 수 있다. 본 구현은 오래된 세대 원본을 자동 영구 보관하지 않으므로 필요한 평가 모델은 제거 전에 별도로 복사해야 한다.

## GPU 사용의 의미

공통 정책 하나는 여러 경기의 판단을 묶기 쉽게 하지만, 그것만으로 GPU 효율이 생기지는 않는다. 이번 구현은 기존의 검증된 CPU 병렬 수집을 사용한다. 여러 경기의 추론 요청을 중앙에서 모으는 GPU 서버나 GPU 물리 시뮬레이터는 구현하지 않는다.

2026-11-04 이 PC의 RTX 3060에서 분리 측정한 추론 결과:

| 정책 / 묶음 크기 | CPU | GPU | 해석 |
|---|---:|---:|---|
| 원본 SAC / 1건 | 0.701ms | 1.237ms | CPU가 빠름 |
| 추가 PPO / 1건 | 0.205ms | 1.013ms | CPU가 빠름 |
| 원본 SAC / 256건 | 3.666ms | 2.260ms | 원시 추론만 약 1.62배 GPU 우세 |
| 추가 PPO / 256건 | 0.743ms | 1.115ms | CPU가 빠름 |

이는 정책의 결정적 행동 추론 비교이며 실제 전체 PPO 갱신이나 학습 완료 시간 비교가 아니다. CPU↔GPU 전송은 포함하고, 기존 합산 GPU 사용량 목표 제어의 의도적인 대기는 제외했다. 실험 원본은 `storage-reports/inference-device-benchmark.json`이다. 실시간 사용률을 엄밀하게 65% 이하로 강제하는 하드웨어 제한이 아니라 기존 소프트웨어의 합산 목표 제어 하에서 실행했다.

GPU를 활용할 다음 실험은 원본 SAC와 격발 정책의 추론을 여러 환경에서 모아 처리하고, 추론 시간뿐 아니라 대기·통신·경기 처리량까지 비교하는 것이다. 정책을 한 건씩 호출하는 현재 구현에서 GPU로 전환하면 빨라진다고 주장하지 않는다.

| 같은 모델 폴더의 `live/slot-0, slot-1` | 두 개의 순환 복구 지점. 모델·옵티마이저·난수·경기 수·상대 목록 |
| 같은 모델 폴더의 `generations` | 학습에 사용하는 최근 2~3세대만 보관 |

리플레이나 프레임 궤적은 매 경기 저장하지 않는다. 내부 전투 계산에 필요한 최신 카메라 끝점만 유지한다. 요약 로그는 묶음마다 flush하고 화면 진행 파일은 통상 최대 초당 2번, 묶음·체크포인트 경계에서 추가 갱신한다. 오래된 모델을 삭제한 뒤 과거 경기 요약만으로 당시 행동을 정확히 3D 재생할 수는 없다. 실제 리플레이가 필요하면 대전 시뮬레이터에서 현재 모델의 행동을 기록해야 한다.

`선택 작업 중단·저장` 후 `이어서 학습`한다. 동일 폴더에서 모델·옵티마이저·난수 상태·상대 세대·누적 경기 수·목표를 복구한다. 세대 주기는 누적 경기 수 기준이라 재시작해도 0부터 다시 세지 않는다. 재개에서는 저장된 조건을 사용하며 목표 총 경기 수만 늘릴 수 있다. 목표는 기본적으로 기존 값 그대로다. 새 조건으로 학습하려면 새 학습을 시작한다.

최신 세대 목록을 복구 체크포인트에 먼저 확정한 후 오래된 모델 파일을 제거한다. 작업별 잠금으로 같은 폴더의 중복 실행을 막고, 서로 다른 작업 폴더에서는 동시에 학습할 수 있다. 기존 경쟁 학습기와 important 모델은 수정하지 않는다.

세대 교체 시에는 두 복구 슬롯 모두 새 상대 목록을 참조하도록 저장한 뒤 이전 세대 파일을 제거한다. 복구된 모델보다 뒤에 쓰인 미반영 경기 요약이 있으면 `recovery-discarded`에 분리하고, 체크포인트의 경기 수부터 다시 진행하여 중복 경기 번호를 방지한다.

CLI:

```powershell
python -m unity_bridge.train_generational --config configs/generational_training.example.json --output generational-results/my-run
python -m unity_bridge.train_generational --resume generational-results/my-run
```
