# 학습기별 변경 아이디어 기록

작성·최근 갱신: 2026-11-05 (한국 시간)

학습기 종류별로 묶고, 각 종류 안에서 날짜순으로 기록한다. 아이디어의 제안·채택·구현을 구분한다.
기존 문서에는 개별 설계 설명과 점검 기록이 있으나, 날짜별 아이디어를 한데 모은 문서는 찾지 못해 이 기록을 만들었다.

## 기록 범위와 날짜 기준

- 이번 대화의 결정과 프로젝트 안에서 확인한 문서·코드·검증 자료에 근거한다. 다른 대화의 내용을 추정해 복원하지 않는다.
- 본문에 날짜가 있으면 그 날짜를 사용한다. 파일 수정일만 확인되는 경우에는 그 사실을 표시한다. 수정일은 최초 제안일이나 실제 구현일을 확정하지 않는다.
- 날짜를 확인할 수 없는 기존 아이디어는 해당 학습기의 ‘날짜 미확인’에 둔다.
- 아래 내용은 확인 가능한 기록을 정리한 것이며, 프로젝트의 모든 과거 아이디어를 완전히 복원한 목록은 아니다.

| 쿨다운 차이 등 불리한 조건의 성공 보상 | 철회 | 현재 양쪽 쿨다운·공격 조건이 공통이므로 적용 전제가 틀림 |
| 연승 유지·연패 탈출 보상 | 철회 | 직전 경기 결과가 현재 정책 입력에 누적되지 않음 |
| 선제타격 추가 보상 | 철회 | 먼저 맞히는 사실 자체를 별도 인간 가치로 취급할 근거 부족 |
| 기여율이 높은 패배에 추가 비용 | 추가하지 않음 | 막타 대기 전략은 기존 α로도 나타날 수 있음. 기여 이력에 따른 별도 선택 차이의 근거가 필요 |

### 2026-11-05 — 보상 정의 확정

```text
총 보상 = 기존 α 보상
        + βD × 실제 누적 피해 / 최대 체력
        + βC × [자신의 Critical 처치 여부]
```

| 항목 | 확정 내용 |
|---|---|
| 기존 α 보상 | 내 처치 `+2α`, 상대 처치 `−2(1−α)`, 단독 승자 없음 0 |
| 누적 피해 계수 βD | 0~1. 실제 체력 감소만 인정하고 초과 피해 제외. 이 항의 최대는 βD |
| Critical 계수 βC | 0~1. α와 독립된 추가 보상. Critical 명중만으로는 지급하지 않음 |
| 검토 후 대체한 안 | 기본 처치 보상에 1~2배를 적용하는 비례항 대신 독립항 채택 |
| ‘2배’ 질문의 의미 | 전체 보상을 2로 나누자는 뜻이 아니라 Critical 배율의 충분성에 관한 질문이었음. 전체 보상 나누기는 채택하지 않음 |

### 2026-11-05 — 별도 학습기 생성·검증

- 기존 자동 세대 학습기를 복사하여 새 학습기 생성. 원래 학습기의 보상 정의는 유지.
- 자기 βD·βC 두 항목을 관측에 추가: v8, 24개 입력. 상대 보상 계수는 공개하지 않음.

## 6. 2026-11-05 — 경기별 상세 기록 저장 축소

- 체크포인트는 보존하기로 결정했다. 일반·고정 상대 순환 학습기는 기존 중간 스냅샷과 복구 슬롯을 유지한다.
- 네 학습기의 경기별 상세 JSONL 저장을 CLI의 `--record-episodes`로 옮겼다. 일반 실행은 학습 설정·진행 요약·복구 체크포인트를 저장한다.
- 자동 세대 학습기 두 종류의 기본 재개는 체크포인트를 사용한다. 상세 기록을 이어 쓰기로 명시한 경우에만 기존 JSONL의 연속성을 검사한다.
- 최신 A/B 복구 모델을 확인한 뒤 완료된 일반 학습 여섯 건의 경기별 상세 기록 약 1.99 GB를 삭제했다.

### 2026-11-05 — 후속 통계용 경기별 결과를 기본 저장

- 일반 A/B, 고정 상대 순환, 자동 세대, 피해·Critical 세대 학습기 모두 `episodes.jsonl`을 기본 저장한다. 경기 번호·시드·승자(`0`은 A, `1`은 B, `null`은 무승부)·소요 시간·보상·발사 및 판단 횟수와 실제 적용 조건을 남긴다.
- 프리셋은 ID만, 상대는 세대 또는 목록 번호를 남긴다. 누적 피해·Critical 학습기는 보상 계수와 항목별 보상도 저장한다. 전체 요청·프리셋 설명이 필요한 분석 실행은 `--record-episodes`를 사용한다.
- 로그가 없는 기존 작업도 체크포인트 다음 경기부터 기록한다. 재개 시 복원한 체크포인트보다 뒤의 기록만 잘라낸다.

## 이후 기록 방식

해당 학습기 항목 아래에 날짜, 아이디어·해결하려는 문제, 채택·기각·보류, 구현 여부, 근거 파일을 덧붙인다.
논의만 한 항목을 구현된 변경으로 기록하지 않는다. 공통 변경은 1절에 쓰고 해당 학습기에서 참조한다.
