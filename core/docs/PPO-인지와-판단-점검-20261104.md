## 1. PPO가 실제로 받는 정보

현재 입력은 47차원이며 `encode_context()`가 만든다.

| 구분 | 입력 내용 | 차원 |
|---|---|---:|
| 공통 상태 | 남은 체력 비율, 남은 체력의 로그값, 자기 외곽/중앙 피해와 남은 체력의 비율, 치명타 반지름 비율, 경과 시간, 상태 갱신 후 경과 시간 | 7 |
| 자기 정보 | 운동·위치·속도·시계 노이즈 계수, 원본 조준 성공/실패 조건 및 각 감쇠 계수, 타겟 크기, 탄 퍼짐, 재장전 시간, 남은 쿨다운, 현재 조준 오차, 현재 치명타 범위 여부, 현재 조준선 기준 피해/체력 비율, 타겟 속도 | 16 |
| 상대 정보 | 위 자기 정보와 같은 항목 | 16 |
| 양쪽 무기 정보 | 각각의 외곽 피해/남은 체력, 중앙 피해/남은 체력, 즉사 활성화 여부 | 6 |
| 자기 PPO 보상 | 내 처치 보상, 상대 처치 시 패배 비용 | 2 |

합계는 7 + 16 + 16 + 6 + 2 = 47이다. HP와 피해는 로그·비율, 시간과 각도는 정해진 상수로 나누어 전달한다. 일부 무기·속도·타겟 크기 정보는 중복된다.

상대의 **추가 PPO 처치 보상·패배 비용은 입력되지 않는다.** 상대의 **원본 조준 성공/실패 조건**은 위 8개 프로필 값에 포함되어 입력된다. 이 둘은 서로 다른 보상 파라미터다.

## 2. 입력 정보의 출처와 정확도

- 체력과 쿨다운은 시뮬레이션 상태에서 계산하며, 추가 지각 노이즈를 넣지 않는다.
- 조준 오차는 실제 카메라 방향과 실제 타겟 위치를 투영해 계산한다. 원본 에이전트의 노이즈가 섞인 지각 추정치를 그대로 전달하는 구조가 아니다.
- 운동 노이즈가 이미 실제 조준 궤적에 준 영향은 현재 오차에 반영된다. 반면 그 순간의 지각 오차나 향후 운동·시계 노이즈 표본 자체는 알려주지 않는다.
- 양쪽의 노이즈 계수와 무기 설정은 알려준다. 앞으로 실제로 추출될 탄 퍼짐 방향은 알려주지 않는다.
- `center_damage_over_hp`는 **현재 조준선이 그대로 적중했을 때의 기하학적 피해값**이다. 명중 확률, 격발 예정 시점의 예상 피해, 탄 퍼짐을 적분한 기대 피해가 아니다.
- 양쪽 공개 상태를 공통 경기 스텝 시작에 먼저 고정하고 진행한다. 상대가 같은 스텝 안에서 앞으로 수행할 행동을 미리 전달하지 않는다. HP·상대 상태는 이 스냅샷 기준이며, 자기 오차와 쿨다운은 PPO 호출 시점에 다시 구성한다.

따라서 위치·속도 지각 노이즈가 커도 PPO는 별도로 더 정확한 현재 조준 오차를 받을 수 있다. 이것은 현재 구현의 정보 공개 방식이며, 의도한 지각 모델과 일치하는지 확인해야 한다.

## 3. PPO가 받지 않는 정보

| 입력되지 않는 항목 | 판단상의 한계 |
|---|---|
| 원본의 현재 발사 요청 여부 `kc` | 같은 상태에서 실제 요청이 있는지 PPO 입력만으로 구분할 수 없다. |
| 이번 제안의 `Th`, `tc`, `kg` | 어떤 발사·조준 제안을 승인하는지 직접 보지 못한다. |
| 이번 계획의 명목 격발 예정 시각 | 현재 쿨다운과 예정 격발 시각을 직접 비교할 수 없다. |
| 쿨다운 적용 후 예정 격발 시각 | 환경이 얼마나 발사를 미룰지 직접 받지 않는다. |
| 격발 예정 시점의 예측 조준 위치·오차 | 현재 오차가 커도 예정 시점에는 맞는 계획인지 직접 평가할 수 없다. |
| 타겟 이동 방향, 손·조준의 이동 벡터 | 거리 오차와 속도 크기가 같아도 타겟에 접근하는 상황과 멀어지는 상황을 완전히 구분하지 못한다. |
| 상대의 발사 요청·승인·진행 중인 계획·격발 예정 시각 | 상대 쿨다운 0을 안다고 해서 상대가 언제 발사할지도 아는 것은 아니다. |
| 상대 PPO의 보상함수 파라미터 | 직접 공개하지 않는다. |
| 설정된 타임아웃과 남은 경기 시간 | 경과 시간은 받지만, 타임아웃을 바꿨을 때 남은 시간을 직접 알 수 없다. |
| 과거 행동·발사·상대 판단의 시계열 | 현재 PPO는 별도 순환 메모리 없이 현재 입력을 처리한다. 상대 행동 이력을 누적해 추론하는 구조가 아니다. |

실행 검증에서 같은 시드·현재 상태를 두고 원본 제안을 다음처럼 바꿨다.

| 제안 | 요청 | Th | tc | PPO 입력 |
|---|---:|---:|---:|---|
| 1 | 없음 | 100ms | 0 | 동일 |
| 2 | 있음 | 100ms | 0 | 동일 |
| 3 | 있음 | 2,000ms | 1 | 동일 |

즉, PPO가 개별 발사 계획의 내용까지 읽고 승인한다고 설명하면 현재 구현과 다르다. 현재는 현재 상태에 대한 승인/보류 성향을 출력하고, 환경이 이를 발사 요청에 적용한다.

## 4. 실제 판단·실행 순서

판단 주기는 기본적으로 100ms BUMP이며, 이미 승인된 계획이 수행 중이면 PPO 호출을 건너뛴다.

1. 원본이 `kc`, `Th`, `tc`, `kg` 제안을 낸다.
2. 진행 중인 발사 계획이 없으면 PPO가 현재 47차원 입력으로 승인/보류를 결정한다. **새 지각 노이즈를 적용한 계획 계산보다 먼저 호출된다.**
3. `kc=1`이고 PPO도 승인한 경우에만 발사 계획을 시작한다. `kc=0`이면 PPO의 승인/보류가 실제 발사 계획 시작에 영향을 주지 않는다.
4. 보류되면 발사 계획을 시작하지 않는다. 조준·시선 처리는 진행하며 다음 BUMP에서 다시 제안한다.
5. 승인되어 시작한 계획은 실제 발사까지 유지한다. 이후 BUMP에서 PPO가 이를 다시 심사하거나 취소하지 않는다.
6. 명목 발사 지연은 `(100ms + tc × Th) × 시계 노이즈 배율`을 바탕으로 정해진다. 실제 구현에는 반올림과 최소 1ms 처리가 있다.
7. 실제 발사는 **예정 시각과 쿨다운 종료 시각 중 늦은 시각**에 일어난다. 쿨다운 중 계획 시작은 허용한다. 이미 승인된 계획을 쿨다운 때문에 취소하지 않는다.
8. 실제 발사 때 탄 퍼짐을 추출하고 타겟 적중·피해를 판정한다. 실제 발사 시각부터 다음 쿨다운을 계산한다.
9. 한 발이 끝나면 진행 중인 계획을 비우고 다음 발사 제안을 받을 수 있다. 타겟 파괴나 경기 종료가 전체 실행을 끝낸다.

PPO의 행동은 승인/보류 2개뿐이다. 조준 방향이나 `Th·tc`를 직접 변경하지 않으며, 쿨다운 때문에 발생하는 지연은 PPO 행동이 아니라 환경의 실행 규칙이다.

쿨다운 수치는 최소 발사 간격이다. 실제 간격에는 제안된 격발 지연과 다음 BUMP까지의 대기 등이 추가될 수 있으므로, 쿨다운 100ms가 항상 100ms마다 탄이 나간다는 뜻은 아니다.

## 5. 보상과 학습 방식

- 내 탄이 공유 타겟을 최종 파괴하면 `+내 처치 보상`, 상대가 최종 파괴하면 `−내 패배 비용`이다.
- 적중·빗나감·피해량·발사·보류 자체에 대한 추가 보상이나 비용은 없다.
- 시간 종료·무처치 및 단독 승자가 없는 동시 처치는 0이다. 타임아웃 음보상은 없다.
- 같은 시각의 탄은 묶어서 처리한다. 파괴에 기여한 즉사 탄이 있으면 즉사 기여자를 우선하고, 최종 처치자가 양쪽이면 무승부다.
- 한 경기의 마지막 PPO 학습 기록에 결과 보상을 넣고 PPO 갱신에서 앞선 판단들에 반영한다.
- 현재 새 PPO 설정은 `gamma=1`, `gae_lambda=0.95`, 엔트로피 계수 0.01이다. 물리 시간에 대한 별도 비용은 없다.
- 발사 요청이 없는 BUMP에서도 PPO를 호출하고, 학습이 켜진 쪽은 그 결과를 학습 기록에 넣는다. 이때 두 선택은 현재 구현상 발사 계획 시작에 영향을 주지 않는다. 이는 무효 행동이 포함된 학습 기록이라는 구현 사실이며, 실제 학습 성능에 미치는 크기는 별도 측정이 필요하다.
- 승인된 계획 수행 중에는 PPO 판단과 학습 기록을 새로 만들지 않는다. 따라서 학습 기록의 한 칸은 항상 물리 시간 100ms를 뜻하지 않는다.

## 6. 학습과 대전의 차이

| 경로 | PPO 행동 선택 |
|---|---|
| 일반 A/B 공동 학습 | 양쪽 정책 분포에서 확률적으로 추출 |
| 일반 학습에서 한쪽 추가 학습 차단 | 그쪽 가중치는 갱신하지 않지만 행동은 여전히 확률적으로 추출 |
| 상대 목록 순환 학습 | 학습 A는 확률적 추출, 고정 상대 B는 저장된 정책의 최빈 행동 |
| 대전 시뮬레이터·모델 평가 리플레이 생성 | 양쪽 모두 저장된 정책의 최빈 행동 |
| 이미 저장된 리플레이 재생 | 모델을 실행하지 않고 행동 기록을 재생 |

공동 학습과 대전은 같은 `DualSession` 발사·피해 경로를 사용한다. 다만 위 행동 추출 방식 때문에 학습 중 관측한 승률과 대전 승률은 같다고 보장할 수 없다.

일반 학습·대전·학습 모델 평가 진입점은 지정 타임아웃을 전체 경기 한도와 무격발 한도에 함께 적용한다. `DualSession` 자체 기본 무격발 한도는 15초이며, 출력의 `no_shots_15s` 문자열은 한도를 덮어써도 고정되어 있다. 남은 한도나 무격발 카운터는 PPO 입력에 없다.

## 8. 실행 검증 범위
